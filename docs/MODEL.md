# Модель кофемашины: архитектура

Источник формы — `ref/hero.png` (фото референса). Пропорции взяты по кадру и
типовым размерам бытовых суперавтоматов: **210 × 390 × 390 мм** (Ш × Г × В).
Машина — узкий высокий «шкафчик»: фронт с золотой панелью, справа паровой кран,
сверху площадка подогрева с бункером для зёрен.

Единицы в Blender — метры (`W 0.210`, `D 0.390`, `H 0.390`). Низ модели на `z = 0`,
фронт смотрит в **−Y**. Экспорт — GLB, Y-up, масштаб 1.

## Дерево объектов

Корень — пустышка `Машина`. Внутри — ровно **16 узлов верхнего уровня**, каждый
с собственным `explode` и `wave` в extras. Имена — человекочитаемые, по-русски:
на сайте подпись берётся прямо из `obj.name`, отдельного словаря нет.

## Разборка

Волны — порядок выезда. Внутри волны узлы стартуют одновременно, между волнами
задержка `0.16` от общего прогресса (`viewer.ts`). Сначала уходят панели (машина
раскрывается), затем лицо, потом навесное, и последними — внутренности.

Векторы пишет `explode_all()` в `build.py` — в метрах, в системе модели.
`viewer.ts` читает `userData.explode` и делит на масштаб, чтобы смещение в ворлде
осталось тем же. `userData.wave` тоже едет в GLB; если его нет — включается
запасная карта `WAVES` в `viewer.ts`.

## Пайплайн

```
# сборка + рендер этапа (1 корпус, 2 внешние узлы, 3 нутро, 4 разборка, 5 всё)
"C:\Program Files\Blender Foundation\Blender 5.3\blender.exe" -b --factory-startup ^
  -P tools/blender/build.py -- --stage 5

# мягкая контактная тень под машиной в постере (после каждого рендера постера)
pwsh -File tools/poster-shadow.ps1
```

`--stage 5` делает всё: рендер `pics/model-stage5.png` (EEVEE, 1600×1200),
прозрачный постер `public/img/model-still.png` (1200×1200, Cycles, 96 сэмплов,
денойз OIDN), экспорт `public/model/machine.glb`, сохранение `machine.blend`.
Файл печатает JSON: список корневых имён, число мешей и фейсов, explode-таблицу.

Тень в постере — не в Blender: плоскость-блоб с радиальным градиентом в Cycles
уходит за кадр при рабочей высоте камеры, а shadow catcher в EEVEE просвечивает
миром. Поэтому тень накладывается отдельным шагом (`tools/poster-shadow.ps1`)
и в вебе рисуется отдельным плейном в `viewer.ts`.

## В браузере

- `GLTFLoader` + `OrbitControls`, разборка через GSAP на общем прогрессе.
- Окружение — не `RoomEnvironment`, а собственная сцена из трёх световых зон
  плюс полоса-горизонт, прогнанная через `PMREMGenerator`: только так тёмный
  металл получает градиентный блик, а золото — мягкое отражение.
- Подписи — DOM: `span.viewer__label` + SVG-выноска (`line` + `circle`) от
  метки к проекции центра детали. Подписи разводятся по двум колонкам,
  появляются на 30–75 % прогресса.
- Hover — emissive всей детали целиком (обход детей узла).
- `dpr` ограничен 2, shadow map выключен, плитка света статична.

**Важно:** `GLTFLoader` прогоняет имена узлов через `PropertyBinding.sanitizeNodeName`
и меняет пробелы на `_`. В модели пробелов, кроме разделителя слов, нет —
`viewer.ts` возвращает их обратно (`name.replace(/_/g, ' ')`). В самом GLB и в
Blender имена канонические, с пробелами.

## Проверка

1. Рендер каждого этапа в `pics/model-stage{n}.png` — глазами.
2. `npx astro check` — 0 ошибок; `npx astro build`.
3. `npx astro preview --port 4401 --host 127.0.0.1` +
   `node tools/shot.mjs "http://127.0.0.1:4401/crema-service/" pics/web-check.png 1440 900 --wait=7000 --json`.
4. В консоли браузера:
   `[...document.querySelectorAll('.viewer__label')].map(e => e.textContent)` — кириллица без «?».

## Что осталось

- «Запуск машины» по кнопке (клиент просил после утверждения модели): сейчас
  кнопка только разбирает/собирает.
- Фактура металла: без текстуры поверхность золота и алюминия идеально гладкая.
  Если понадобится — либо bake в текстуру (тогда GLB потяжелеет), либо лёгкий
  шум в шейдере только для постера.
- Ниша под чашку глубиной 72 мм при студийном свете читается тёмной: лоток виден
  частично. Лечится наклоном камеры или подсветкой изнутри.
