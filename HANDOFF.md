# Передача проекта — для ИИ-агента

Документ для агента, который продолжит работу или соберёт похожий сайт.
`docs/ARCHITECTURE.md` отвечает «как устроено», этот файл — «что дальше, почему так и как переделать под клиента».

Читать сверху вниз: контекст → устройство → как менять. Не дублировать содержимое `AGENTS.md`
(стек и правила) и `~/.dsh/rules/architecture.md` (принципы) — здесь только то, чего там нет.

---

## 1. Контекст

- **Что это:** шаблон клиентского сайта VOIDCODE на Astro. Не готовый сайт, а каркас: структура,
  контракты в шапках файлов и `TODO` вместо контента.
- **Зачем:** новый клиентский проект стартует за копирование папки, а не за переизобретение структуры.
- **На чём основан:** разбор проекта `design-references\apm-site` (APM «Индекс») и `arka-estate`.
  Принципы — в `~/.dsh/rules/architecture.md`. Композицию референсов не копируем.
- **Состояние:** скелет собирается (`npm run build` — 0 ошибок), проверки настроены, контента нет.
- **Кому:** Ильяс (VOIDCODE). Тон — сухой, технический, без украшений.

### Что шаблон решает

| Проблема обычного старта | Решение в шаблоне |
|---|---|
| Контент вперемешку с разметкой | `src/data/` — единственный источник фактов |
| Главная растёт в один файл на 1500 строк | `src/components/sections/` — по файлу на блок |
| Палитра расползается по компонентам | `src/styles/tokens.css` + поверхности |
| «Готово» без проверки | `npm run verify` — типы, контраст, скриншоты, структура |
| Фото взяты откуда попало | `tools/fetch_photos.py` + манифест атрибуции |
| Агент делает `git add .` и читает `.env` | `.claude/settings.json` — исполняемые запреты |
| Непонятно, что дальше | этот файл |

## 2. Концепция и дизайн-система

**Палитра по умолчанию нейтральная и доступная.** Это стартовая точка, а не бренд: под клиента
меняются значения примитивов в `:root`, а не компоненты. Все пары проверены `tools/contrast.mjs`.

| Токен | Значение | Роль | Контраст |
|---|---|---|---|
| `--paper` | `#FFFFFF` | светлая поверхность | — |
| `--ink` | `#14161A` | текст, тёмная поверхность | 18.11:1 на paper |
| `--ink-2` | `#1E2229` | подложка на тёмном | paper 15.96:1 |
| `--mist` | `#F1F2F4` | нейтральная подложка | ink 16.17:1 |
| `--muted` | `#5B6169` | вторичный текст на светлом | 6.25:1 |
| `--muted-d` | `#B4BAC4` | вторичный текст на тёмном | 9.28:1 |
| `--accent` | `#17557F` | заливки, ссылки, фокус | 7.95:1 |
| `--accent-d` | `#6FA8D0` | акцент на тёмных поверхностях | 7.06:1 |
| `--on-accent` | `#FFFFFF` | текст на акцентной заливке | 7.95:1 |
| `--on-accent-2` | `#C7DCEA` | вторичный на акцентной заливке | 5.62:1 |
| `--line` | `#808790` | границы полей ввода (норма 3:1) | 3.63 на paper / 3.24 на mist |
| `--hairline` | `#D5D8DD` | декоративные линии, без нормы | — |

**Правила цвета.**
- Сырой `#hex` — только в `tokens.css`. В компоненте — `var(--…)`. Иначе ошибка ревью.
- Секция объявляет поверхность: `surface-paper | surface-mist | surface-ink | surface-accent`.
  Семантика (`--bg`, `--fg`, `--fg-muted`, `--hairline`, `--focus`) переключается сама.
- Белый текст можно только на `--accent` и `--ink`. На `--paper` — никогда.
- `--line` — для границ интерактивных полей (норма 3:1, WCAG 1.4.11). `--hairline` для декора — нормы нет.

**Шрифты.** В шаблоне — системный стек через `--font-text`. Самохостинг (`@font-face`, woff2,
фолбэки с `size-adjust`) добавляется под проект: без Google Fonts и CDN.

**Движение.** Одна осмысленная анимация на проект, остальное — ответ на действие.
Скрытие до анимации только под `html.js`, только ниже первого экрана; `reduce` отключает всё.
Бюджет: блок ≤ 2 с, сдвиги ≤ 24 px.

## 3. Структура страницы (по порядку)

Порядок объявлен в `src/pages/index.astro` и только там. В шаблоне три секции-заглушки:

1. **`Hero.astro`** — первый экран. Заголовок, подзаголовок, действие. Главный визуал проекта.
2. **`Services.astro`** — услуги. Читает `SERVICES`, работает без JS, список деградирует корректно.
3. **`Contact.astro`** — контакты и заявка. Читает `CONTACTS`; пустое поле не выводится.

Под проект добавляются: `Cases`, `About`, `Trust`, `Team`, `Footer` (общий — в `components/`, не в `sections/`).
Правило: один блок макета = один файл. Секция не импортирует другую секцию.

## 4. Стек и файлы

- **Astro 7.4.7** (static, `dist/`), TypeScript strict, `@astrojs/check 0.9.12`, `typescript 6.0.3`.
  Версии зафиксированы точно: `^` не используем, обновление — отдельным решением.
- Без UI-фреймворков и без библиотек анимации. CSS + нативные скрипты. Причина — см. §7.
- Скрипты: `npm run build` = `astro check && astro build`; `npm run verify` — полная проверка; `npm run photos`.
- Деплой — статика на любой хостинг. Домен — в `astro.config.mjs` (`site`), нужен для абсолютных OG.


## 5. Данные

`src/data/site.ts`:
- `SITE` — `name`, `legalName`, `url`, `locale`, `title`, `description`.
- `CONTACTS` — `phone`, `phoneHref`, `email`, `emailHref`, `address`, `telegram`.
- `NAV`, `SOCIALS` — массивы; пустые, пока нечего выводить.

`src/data/services.ts`:
- `Service` — `id` (latin kebab-case: идёт в якоря и ссылки), `name`, `summary`, `includes[]`,
  `price?`, `term?`.
- `SERVICES: Service[]` — пусто до утверждения плана.

**Правила данных.**
- Нет факта — нет строки. Не выдумывать цифры, цены, сроки, отзывы.
- В шапке каждого файла — источник фактов (бриф, сайт клиента, презентация, договор).
- Пустое поле не выводится, а не заполняется заглушкой.
- Типы выводятся из данных (`type X = (typeof LIST)[number]['id']`), а не дублируются руками.
- Добавление записи не должно требовать правок в компонентах. Если требует — структура данных неверна.

## 6. Как устроен главный элемент

В шаблоне главного элемента нет — и это правильно: его придумывает план под конкретного клиента.

**Куда он приходит.** Отдельный компонент в `src/components/`, импортируется одной секцией
(обычно `Hero`). Не в `sections/`, если это не блок страницы целиком.

**Что должен уметь главный элемент.**
- Быть понятным без JS: контент в разметке, а не собран скриптом.
- Иметь один осмысленный приём движения, а не три.
- Не требовать библиотеки анимации.
- Работать на 390 и на 1920 без горизонтального скролла.
- Иметь осмысленный `alt` либо быть декоративным с `aria-hidden`.

**Пример из практики (не копировать композицию, копировать дисциплину).** В `arka-estate` главный
элемент — SVG-фасад с окнами: окна зажигаются при загрузке, за окном с ценником стоит объект.
Три инварианта, которые там пришлось держать вручную: позиции продающихся окон в `PATTERN` обязаны
совпадать с `saleWindows`; ценники рисуются отдельным верхним слоем, иначе их перекрывает этаж ниже;
на сервере рендерится тёмный фасад, иначе гидрация расходится. Вывод для нас: если главный элемент
держит несколько связанных состояний — это уже не «секция», а повод для отдельного слоя логики (§7).

## 7. Состояние и сценарии

**В шаблоне состояния нет.** Всё статично. Это осознанно: Astro выбран для контентных сайтов.

**Правило выбора стека.** Astro по умолчанию. Next.js — только если на странице больше **двух
связанных интерактивных состояний** (модалка с фокус-трапом, квиз, фильтр каталога, связка
«объект → заявка»). Тогда статикой это делается ценой шести несвязанных скриптов — как было
в `apm-site`. Подробнее — `~/.dsh/rules/architecture.md`, раздел «Выбор стека».

**Если состояние всё-таки нужно в Astro.**
- Один модуль на сценарий в `src/scripts/`, вход — один `main.ts`.
- Общее состояние — один объект, а не `data-` атрибуты, разбросанные по разметке.
- Работа без JS: разметка и ссылки должны давать результат и без скрипта (форма — обычный POST, фильтр — серверный или `<details>`).
- Модалка: фокус-трап, `Esc`, возврат фокуса на открывшую фокус кнопку, блокировка скролла.
- Фоновые вкладки: `requestAnimationFrame` не срабатывает — для «показать после монтирования» брать `setTimeout`.

**Формы.** Демонстрационные формы помечаются «демо» и ничего не отправляют. Рабочая форма требует
обработчика и согласия на обработку ПДн (152-ФЗ); до этого форма не считается готовой.

## 8. Адаптив и проверка

**Точки перелома** — задаются под проект. Минимум, который обязан работать:
1440 и 390 (проверяются машинно), плюс 320 и 1920 глазами на первом прогоне.

**Что проверяется машинно** (`npm run verify`):

| Шаг | Инструмент | Что ловит |
|---|---|---|
| Типы | `astro check` (внутри `build`) | ошибки в данных и пропсах |
| Сборка | `astro build` | битые импорты, падение рендера |
| Контраст | `tools/contrast.mjs` | пары ниже 4.5:1 текстом и 3:1 границами |
| Скриншоты | `tools/shot.mjs` 1440×900 и 390×844 | горизонтальный скролл, пустой кадр, ошибки консоли |
| Структура | `tools/predeploy-check.mjs` | `TODO`, плейсхолдеры, `localhost`, битые ссылки, отсутствие OG/robots |

**Проверки руками, которые автоматика не заменяет:** клавиатура (Tab по всей странице, фокус виден),
`--reduce` (ничего не движется), без JS (всё читается), 320 px (ничего не липнет).

**Горизонтальный скролл** — отдельное правило: `scrollWidth === innerWidth`. `shot.mjs` падает с exit 1,
если это не так.

**Скриншот смотреть глазами.** Наличие файла — не проверка.

## 9. Фото

Два режима, выбор осознанный.

**1. Скачанные — для hero и ключевых блоков.** `tools/fetch_photos.py` кладёт файлы в `assets/photos/`
и пишет `photos.json` с автором и ссылками. Плюс: нет зависимости от чужого CDN, снимок не изменится.
Минус: вес в репозитории. Поэтому — только там, где фото незаменимо.

**2. Хотлинк — для галерей и списков.** `img()` / `srcSet()` из `src/lib/images.ts` строят
`images.unsplash.com/photo-…?auto=format&fit=crop&w=…&q=72`. Ноль веса, отдаётся CDN с ресайзом.
Минус: зависимость от Unsplash; для галерей это приемлемо.

**Лицензия.**
- Только бесплатная лицензия. `plus.unsplash.com` — **платная Unsplash+**, брать нельзя. Скрипт отсеивает.
- Атрибуция обязательна: автор + ссылка. `photoCredit()` в `images.ts` читает `photos.json`.
- Манифест не удалять и не обнулять.

**Отбор.** Смотреть картинки контакт-листом, а не по описанию — описания врут про свет и композицию.
Подбирать под палитру проекта, а не «первое красивое».

**Нейрогенерация — крайний fallback.** Когда реального фото нет и получить его не у кого. В клиентском
проекте сгенерированное фото — риск претензии; в интерьере, недвижимости и промышленности фальшивку видно сразу.

## 10. Команды

```bash
npm install
npm run dev                  # http://localhost:4321
npm run build                # astro check && astro build → dist/
npm run verify               # типы + сборка + контраст + скриншоты + структура
npm run contrast             # только контраст пар
npm run shot -- <url> <out.png> 1440 900 --full --scroll
npm run predeploy            # строгий гейт перед выкладкой (валит на TODO)
npm run photos -- "запрос" -n 5
```

**Время и порты.** Предпросмотр — порт **4321** (зафиксирован в `.claude/launch.json`), чтобы проверки
были воспроизводимы. Скриншоты `verify` кладёт в `.cache/verify/`.

**Chrome для скриншотов.** Путь не захардкожен: `CHROME_PATH` → типовые пути Windows/macOS/Linux →
`chrome`/`chrome.exe`/`msedge` из `PATH`. Если браузер не найден — `shot.mjs` падает с понятным
сообщением, а не молча.

**Деплой** — только по явной команде. Перед ним: `npm run verify` и `npm run predeploy`.

## 11. Как переделать под реального клиента

1. **План.** `plans/YYYY-MM-DD-<slug>.md`: цель, отличие от референса, система (цвет, шрифты, образ),
   kill list, фазы. Вывести в чат на утверждение. Без утверждения не код.
2. **Домен и мета.** `astro.config.mjs` → `site`; `src/data/site.ts` → `SITE.title/description`.
3. **Контакты.** `CONTACTS` — телефон, почта, адрес, Telegram. Пустые поля не выводятся.
4. **Палитра.** Примитивы в `:root` `tokens.css` → прогнать `npm run contrast` → поправить пары,
   которые не прошли. Не менять компоненты под цвет — менять токен.
5. **Данные.** `SERVICES`, дальше `cases.ts`, `legal.ts`. Каждый факт — с источником в шапке файла.
6. **Секции.** Добавить файлы в `sections/`, порядок — в `index.astro`. У каждой секции свой `id`.
7. **Фото.** Hero — скачать, галереи — хотлинк. Атрибуцию вывести.
8. **Юридическое.** Реквизиты оператора ПДн, согласие, политика — до деплоя. `predeploy` не пустит.
9. **Проверка.** `npm run verify` → посмотреть скриншоты глазами → `--reduce` и без JS → 320 px.
10. **Ретро.** `retrospectives/` по шаблону: Задача · Как решали · Было → стало · Уроки · Открыто.

**Что менять нельзя:** структуру `src/data` ↔ `src/components/sections`, правило токенов, порядок
секций в одном файле, обязательность `npm run verify` перед сдачей.

## 12. Что не сделано

- **Секции-заглушки без контента.** `Hero`, `Services`, `Contact` — каркас. Наполняются планом.
- **Самохостинг шрифтов не подключён.** Есть `--font-text` с системным стеком; `@font-face` и
  сабсеты (кириллица + ₽) — под проект.
- **Нет `src/data/legal.ts`** и страниц политики/согласия. Нужны, если на сайте есть форма сбора данных.
- **Нет формы.** `Contact` выводит только контакты. Обработчик (API/бот/CRM) — отдельное решение,
  и тогда 152-ФЗ: хранение в РФ, уведомление РКН.
- **Нет OG-картинки и рецепта её съёмки.** Рецепт: `npm run shot` с **прод-сборки** (`astro preview`),
  иначе в кадр попадут dev-артефакты.
- **Нет sitemap и robots.** Добавляются `@astrojs/sitemap` + `public/robots.txt` при появлении домена.
- **`predeploy` намеренно валит шаблон** — в нём `TODO`. Это правильное поведение: шаблон не деплоится.
- **Проверки не покрывают доступность автоматически.** Клавиатура, `aria`, порядок заголовков — руками.
